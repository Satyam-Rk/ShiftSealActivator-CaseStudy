# ShiftSealActivator-CaseStudy

> **Offline device-bound activation utility for ShiftSeal**

## Overview

**ShiftSeal Activator** is a lightweight .NET 8 utility created to generate activation keys for ShiftSeal installations.

It is designed to support **offline licensing**, allowing a ShiftSeal installation to be activated without requiring a licensing server or internet connection.

---

## Problem

ShiftSeal is designed to operate offline, so a traditional online licensing system would introduce an unnecessary dependency.

The activation system needed to:

* Work without internet connectivity
* Associate an activation with a specific device
* Generate a unique device-based activation key
* Validate the key locally within ShiftSeal

---

## Solution

The Activator takes the device code generated by ShiftSeal and produces an activation key using the same predefined cryptographic rules used by the application.

```mermaid id="u8xqrm"
flowchart LR
    A[ShiftSeal Installation] --> B[Device Code]
    B --> C[ShiftSeal Activator]
    C --> D[Cryptographic Processing]
    D --> E[Activation Key]
    E --> F[ShiftSeal]
    F --> G[Local Validation]
```

No activation server or internet connection is required.

---

## Key Design Decisions

### Offline Activation

The activator is intentionally designed as a local utility.

**Why?**

ShiftSeal itself is offline-first, so licensing should not introduce an internet dependency.

### Device-Bound Activation

The activation process uses a device-specific code so that an activation key is associated with the intended installation/device.

This helps prevent the same activation key from being freely reused on unrelated devices.

### SHA-256

SHA-256 is used as part of the cryptographic processing involved in generating and validating activation data.

The important principle is that both the Activator and ShiftSeal follow the same deterministic rules for generating and validating the activation value.

### Separation from the Main Application

The Activator is maintained separately from ShiftSeal.

```text
ShiftSeal
   │
   └── Generates Device Code

ShiftSeal Activator
   │
   └── Generates Activation Key
```

This keeps the activation-generation process separate from the main application's runtime workflow.

## Security Considerations

The public case study does not expose:

* Private salts
* Activation-generation secrets
* Internal validation rules
* Production licensing configuration

The Activator is intended as a controlled administrative utility rather than a general-purpose key generator.

---

## Outcome

The ShiftSeal Activator provides a simple **offline licensing mechanism** that fits the application's offline-first architecture while associating activation with a specific device.

> **Repository purpose:** This repository documents the activation architecture and engineering approach. Production secrets and private licensing configuration are intentionally excluded.
